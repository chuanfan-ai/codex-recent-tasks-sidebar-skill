# 本机AI状态栏：首批外部灰测计划

更新日期：2026-07-28
目标版本：2.1.0（Build 10）
重点产品：WorkBuddy、TRAE Work

当前放行结论：TRAE Work 可在本项目安装包完成 Apple 公证后进入 G1；WorkBuddy 5.3.5 因首次启动后破坏自身签名包的密封资源，暂停外部安装灰测，等待官方修复包或可验证说明。两款产品仍保留在同一重点清单中。

## 1. 决策与边界

灰测目标是验证两款产品在同一 240 像素窄栏中的真实适配能力、不可用回退和隐私边界。

- WorkBuddy 5.3.5 显示应用包内官方 Logo、安装/运行状态，以及公开 REST 契约返回的当前和最近会话摘要。
- TRAE Work 显示应用包内官方 Logo、安装/运行状态；线程和余额在没有稳定外部契约时显示“—”。
- 两款产品都不承诺余额或单任务精确跳转；WorkBuddy 的线程能力不扩展到未经验证的版本。
- Codex、QwenWorkCN、Kimi 的既有能力必须保持稳定，任一新适配器失败不得影响其他产品。
- 灰测反馈与验收证据不采集任务名称、项目名、账号、文件路径、会话 ID、日志、数据库内容或屏幕正文。
- 没有 Developer ID 签名与 Apple 公证的安装包不得发送给外部用户。

被否决路径：通过通用方式抓取 WorkBuddy 或 TRAE Work 的日志、数据库、DOM、调试端口或界面文本。该路径接入快，但无法形成稳定契约，也会引入隐私与误报风险。

## 2. 建议批次

| 批次 | 建议窗口 | 人数 | 目的 | 放行条件 |
|---|---|---:|---|---|
| G0 本机封闭验证 | 2026-07-28–2026-07-29 | 1 | 连续运行、升级、退出与重启 | 无崩溃、无误报、QA 全绿 |
| G1 邀请灰测 | 2026-07-30–2026-08-05 | 3–5 | 先验证 TRAE Work；WorkBuddy 解阻后补入 | 所有阻断指标达标 |
| G2 小范围扩容 | 2026-08-06–2026-08-12 | 10–15 | 验证支持成本与上游版本差异 | G1 无隐私事件且发现准确 |

TRAE Work 的首轮 G1 样本至少包含 3 名用户和 1 台没有安装目标产品的干净 Mac。WorkBuddy 解阻后的补充样本至少包含 2 名 WorkBuddy 用户，并补做 1 名同时使用两款产品的用户。优先覆盖 Apple Silicon 与 macOS 13–26。

## 3. 测试矩阵

每位灰测用户只需勾选结果，不提交任务截图或诊断原文。

| 场景 | 预期 |
|---|---|
| 两款均未安装 | 两行均为“未安装”，三类既有 Agent 正常 |
| 仅安装 WorkBuddy | 只识别 WorkBuddy，不误识别 TRAE |
| 仅安装 TRAE Work | 识别 `TRAE SOLO.app` 为 TRAE Work |
| 仅安装 TRAE IDE | 不把 TRAE IDE 识别为 TRAE Work |
| 应用已安装但未运行 | 显示“已安装”，任务与额度为空 |
| WorkBuddy 5.3.5 运行且公开端点可用 | 显示当前/最近会话摘要，余额显示“—” |
| WorkBuddy 版本未验证或只读通道不可用 | 线程数和线程区显示“—”，不回退到猜测值 |
| TRAE Work 运行中 | 显示“运行中”，线程和余额显示“—” |
| 应用退出与重启 | 30 秒内更新运行状态 |
| 单个适配器检查失败 | 其他产品继续刷新，不保留误导状态 |
| 点击产品行 | 只打开对应应用，不承诺跳到某个任务 |
| 无网络或登录过期 | 元数据发现仍可用，不尝试提取凭据 |
| 240 像素窄栏 | 五款产品名称保持平级，两款产品使用官方 App 图标，线程与余额区域不截断 |
| 左右吸附与自由置顶 | 位置切换正常，底边对齐不回归 |

## 4. 核心指标与停线条件

G1 放行指标：

- 目标产品发现准确率：100%。
- TRAE IDE 误识别：0。
- 进程数误报为活动线程：0。
- 新适配器导致既有 Agent 不可用：0。
- 安装、首启与基础识别在 10 分钟内完成的用户比例：至少 80%。
- 崩溃、卡死或无法退出：0。
- 隐私越界或敏感信息进入反馈材料：0。

立即停线：

- 读取或显示任何未授权任务正文、账号、凭据或会话内容。
- 误改任务、未读、归档或应用数据。
- 目标产品未运行却持续显示“运行中”。
- 安装包签名、公证或来源验证失败。
- 目标产品首次启动后改变自身签名包，导致严格签名或 Gatekeeper 复验失败。
- 新适配器故障导致 Codex、QwenWorkCN 或 Kimi 整体不可用。

## 5. 反馈与证据

每位用户仅反馈：Mac 芯片、macOS 大版本、安装了哪些目标产品、识别是否正确、状态更新时间、是否崩溃、问题复现步骤。截图必须裁掉任务区、账号区和本机路径。

每次灰测发布保存：

- 版本号、构建号和安装包 SHA-256。
- Developer ID 与公证结果。
- `./scripts/qa.sh` 结果。
- 干净 Mac 的安装、启动、更新、退出与卸载记录。
- 按场景汇总的通过/失败数量，不保存任务内容。

## 6. 两款产品的推进顺序

1. WorkBuddy：保留首批优先级，但 5.3.5 首次启动后会在签名包内新增 `editor_sdk.log`，已触发严格签名与 Gatekeeper 失败。官方修复包或可验证说明出现前，只做公开版本跟踪，不邀请外部用户安装测试。
2. TRAE Work：先进入可放行路线，重点验证官网产品名、下载包名与本机 `TRAE SOLO.app` 的映射，并持续排除 TRAE IDE。
3. WorkBuddy 的公开会话摘要已进入“部分支持”，仅覆盖已验证的 5.3.5 版本；余额与精确跳转继续等待公开契约。
4. TRAE Work 只有发现官方公开接口或稳定外部只读协议后，才开启“部分支持”实验；此前不使用私有接口、日志、数据库、DOM 或调试端口。
5. 任一新增能力进入“部分支持”前，必须新增固定合成测试库、失败回退、数据来源说明和版本闸门。

## 7. 下一放行门

G1 邀请发出前还需完成：

- Developer ID 签名与 Apple 公证。
- 一台干净 Mac 的安装、启动和卸载复验。
- 对外隐私说明与支持矩阵回读。
- 一个不接收任务内容的反馈入口。

WorkBuddy 补入 G1 前还需完成：

- 官方修复包在首次启动前后均通过 `codesign --verify --deep --strict` 与 Gatekeeper 复验，或官方提供可独立验证的等效解决方案。
